## 3 · Findings the eval itself produced

**F1 — the cold-day rehearsal is wall-clock dependent (harness defect, not a planner regression).** Both scenarios
fail at 17:30 local (5 + 2 checks) and pass at 01:00; the bisect at the #152 commit fails identically now. Cause:
`computeShadowPlan` puts the daily 140 °F soak at the warmest *remaining* hour of today; for a falling cold-morning
forecast run in the late afternoon that hour is *now*, so (a) the driver refuses to draw beside a soak within 3 h,
(b) the current block is the soak, so the demand floor (141.6 °F) rides the soak's 145 °F ceiling and the auto-pilot
writes 142–143 °F, which the assertions read as an everyday write above the 135 °F cap. Fix: the fake forecast must
place today's warmest remaining hour ≥ 4 h ahead by construction (or skip today's soak when < 6 h remain), so the
sequence plan → act → draw is the same at any hour. Until then the harness proves nothing at most hours of the day.

**F2 — a demand floor on the soak hour keeps the soak's ceiling and loses the soak's reason.** shadow.ts: when the
floor exceeds the soak target, `reason` is rewritten to "binding zone …" while `sani` stays true, so the block is
written up to 145 °F (soak cap) under a demand-floor reason. Bounded (the soak hour is an excursion anyway) but the
poster and the driver see the wrong identity. P3.

**F3 — the auto-pilot infers "this is the sanitize excursion" from magnitude** (`target > strictCapF ⇒ cap =
sanitizeCapF`). Today unreachable for non-soak blocks because the plan clamps them, but it is a cap that depends on
an invariant two files away. Pass the block's `sani` flag instead. P2 hardening.

**F4 — Phase B Modbus flakiness on both pumps** (table above) plus FINDING-1: no revert lease armed, so a planner
outage leaves pump targets wherever they were. Recorded on #76 with the four-day table.

**F5 — co-serving cannot learn in September.** 0 of 70 pairs proposed; heat-response and load-sharing components
have no events. Recorded on gtm#1617 with the run record and the 365-day-scan recommendation.

**F6 — the pre-boost write is unobservable from outside prod.** `/health.dhw` shows the learned windows and boost
sizes, not whether the 08:00 pre-boost was written. Add `lastPreBoost {at, toF, windowStart}` to `/health`.

**F7 — five pushes to a TempIQ PR got zero GitHub Actions runs;** a "no pending checks" watcher read green. Local
CI-equivalents were run and the real bracket came back after merging main into the branch. Memory note written.
